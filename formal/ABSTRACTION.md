# Core-model abstraction

This document maps the core model to the ComputeNet kernel at commit `dfd5faf7`. The mapping is anchored to named symbols rather than line numbers: when the kernel changes, re-verify every row against the named symbol before treating the mapping as current. The model deliberately checks the decided semantics; this map is not evidence that the implementation already conforms to every modelled rule.

`P02` is a plain state invariant over the `released` history, not a snapshot of a
history variable and not an action assertion. It remains sound while `floor`
and `open` move: an `EdgeOpen` writes its floor once from `flushedHigh`, so every
already-released counter is at or below the new floor and does not become a
retroactive obligation; an `EdgeClose` only removes an obligation; every later
release is checked against the then-current open/floor predicate. `suspended`
still does not move in this family. `releaseWitness` lets P16 assert the stronger
release-time post-install condition directly.
`P03` is an action property, written as `[][... ]_vars`; consequently its
`MCWatermarkRegress.cfg` control reports an action-property violation (exit 13).

P10 and P11 are `~>` liveness properties under `CutSpec`, not step-counter
bounds. Their effective bound is structural: TLC explores the finite graph, and
`QuiescentStutter` keeps a stranded join live long enough for temporal checking
instead of reporting the terminal state as a deadlock.

The `MCNoAbsorbAck.cfg` deadlock is reported during TLC's safety pass before
its listed `P05` temporal property is evaluated. It therefore remains the
control for the load-bearing no-ack stall and names the deadlock as its
expected outcome; `MCUnackedAbsorb.cfg` is the separate direct P06 control.

No control names `P05`, and none can under the harness's flags without a spec
change. `Terminating` requires every frontier's `pending` to be empty, and
every other action is finite: emission is bounded by `WaveBound` and each
delivery moves a message one hop down an acyclic graph. A wave that is still
pending when emission and delivery are exhausted therefore leaves a state with
no enabled action, which TLC reports as `Deadlock reached.` before it
evaluates any temporal property. The device that frees `P06` does not carry
over: with `IgnoreArm = {"cd"}` the frontier no longer waits on the unacked
arm, no wave is stranded, and `P05` holds. Observed in direct serial TLC runs
(`-workers 1`, Darwin arm64, OpenJDK 25.0.2, 2026-10-11): `MCNoAbsorbAck.cfg`'s
constants with only `PROPERTY P05` exit 11; `MCUnackedAbsorb.cfg`'s constants
with `PROPERTY P05` in place of `P06` exit 0; the former with TLC's
`-deadlock` flag, which the harness must not pass, exits 13.

## Non-properties

No P01–P17 entry is dropped: P01–P06 and P08–P16 are stated in TLA+, while P07 and P17 are expressed by deliberately broken controls. P06 is near-definitional because acknowledgement is enqueued in the same model action that records absorption; its load-bearing consequence is P07. P14 is similarly near-definitional because `InstanceSwap` explicitly leaves the wave-plane tuple unchanged; its control proves the seam by injecting a marker. P17 is control-only like P07: it keeps the concrete torn-release consequence of counting a baseline even though P15 already states the safe branch. Both P14 and P17 are retained rather than softened. P01 recognizes absorption only at the producer one hop above the lagging edge. Those are limitations of the abstraction, not reasons to discard any property.

## Limitations

- A non-frontier pass-through cell forwards `Progress` unconditionally. The kernel's `relayAbsorbAcks` unary form relays only while the hop has exactly one open `LinkRole.Consume` input edge. Every pass-through cell in these configurations is unary, so the behaviors coincide here.
- G-36 single-hop edge markers are modelled faithfully: `NonFrontierMarkerDelivery` consumes `EdgeOpen`/`EdgeClose` without forwarding. The BS-7 stranding in `doc/formal/findings.md` is the point of that fidelity, not an abstraction accident.
- `ReBaseline` does ride reactive re-emission: `FanOutlet.call` copies `MessageContext` while changing only `sourcePort`, `hop`, and (when absent) `baseline`, so `reBaseline` is preserved. `WaveFrontier.kt` has no ReBaseline/supersession consumer at `dfd5faf7`; the model's frontier-side `retired` transition realizes the decided 20/22 rule, while `WaterlineCell.forget` is the concrete kernel consumer inspected here.
- The model emits one abstract `Delta(s,t)` per release per outgoing edge. `WaveFrontier.flushReady` instead invokes every buffered contribution's release callback under the shared timestamp.
- A wave absorbed on every arm creates no pending delta, is never released, and emits no downstream acknowledgement. The nested all-absorbing case remains a scenario-gap candidate.
- A `Progress` delivered to a frontier advances its watermark and is consumed; it is never forwarded. This matches the `Protocols.Progress` handler in `WaveFrontier.registerHandlers`.
- Absorption is nondeterministic, while kernel operators decide from their payloads; P01 observes absorption only one hop upstream.
- Delivery, absorption acknowledgement, and release are atomic model actions. Kernel attention bands, intake, parking, coalescing, handler failures, and inter-thread timing are absent; only FIFO order is retained.
- Ownership, wire encoding, and durability/replay mechanics are absent.
- Local and bridged edges are the same model object. Location transparency is assumed, not proved ([22-GF-03]).
- Floors are exact maps for every model source. Their representation and retention/compaction horizon — the open G-39 question — are not modelled. `floor` and `open` move; `suspended` remains inert.
- `CutSpec` adds `QuiescentStutter` only for the cut family so an empty-channel stall with pending waves is a named liveness counterexample. Core `Spec`/`Terminating` behavior is unchanged for the original family.
- A source excluded from `EmitFrom` stays silent for the whole run. The model does not cover a source that emits in one wave and then becomes silent.
- `FrontierDelivery` advances the watermark before its late-delta branch. At `dfd5faf7`, `WaveFrontier.offer` releases a delta at or below `flushedHighWater` without calling `advanceWatermark` or `flushReady`. P01 compares only last-applied counters, so a two-wave flush in one transition could mask a torn earlier wave; per-link FIFO makes that behavior unreachable in the default configurations.
- The `Carries` mismatch is an unverified code-reading divergence, not a reproduced runtime failure or a formal-model finding (`computenet-pu4fi`).
- The harness accepts only exits 11/12/13 whose log contains the cfg's exact declared `Error:` line; a temporal expectation must name exactly one `PROPERTY`. TLC still does not name which temporal property failed, so the one-property rule is the attribution boundary.
