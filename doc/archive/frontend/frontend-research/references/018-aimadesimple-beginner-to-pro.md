# Summary

A beginner-to-pro progression covering usage economics as much as prompting technique — the most explicit
source in this set about quota/cost management as part of the "workflow," not an afterthought.

## Five techniques

1. **Strategic model routing**: route only the hardest problems to Fable; delegate routine tasks to Opus or
   Sonnet, since Fable "burns through usage limits roughly 2x faster than Opus."
2. **Simplified prompting**: replace step-by-step instructions with three essentials — desired outcome,
   non-negotiable constraints, and who benefits/why it matters. States plainly that "context beats
   instructions on this model, every single time."
3. **Lean configuration files**: trim CLAUDE.md-style project files to three elements — project summary,
   essential commands, non-obvious conventions — to reduce noise competing for the model's attention.
4. **Manager-over-worker mindset**: position Fable as a planning/review supervisor delegating execution to
   cheaper subagents, rather than as the one doing the work itself.
5. **Autonomous goals with verification**: use goal-oriented commands with concrete, "visible evidence"
   success criteria and hard stopping limits to enable genuinely hands-off runs.

## Relevance to this project

Reinforces, from an economics angle, the same routing/orchestration pattern found in `009` and `017`, and
gives the clearest, shortest statement of the "context over instructions" principle that recurs across
`001`, `007`, and `013` — worth using as the closing rule-of-thumb in the prompting guide.
