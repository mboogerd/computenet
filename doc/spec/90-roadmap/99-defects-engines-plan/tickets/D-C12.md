(`doc/spec/90-roadmap/91-gap-analysis.md:20`):

> Landed RESTART restores the spawn-time checkpoint and continues emitting
> under the same outlet sourceId/counter (tag/wave aliasing possible) —
> Decided rule (93 I-22, reconciled): restore the freshest checkpoint + fresh

(`doc/spec/90-roadmap/93-feature-interactions.md:8073`, rules R1–R5 at

## Problem

The repository asserts three mutually contradictory things about the same
mechanism. Transcribed precisely:

**Side 1 — the dispute ledger says the kernel contradicts the decided design.**
`concord/corpus/DISPUTES.md:311-349` states: the twelve-verb driver SPI has no
restart/rebaseline verb; `restore(hostId, cellId, blob)` is a raw
`Stateful.restore` with no propagate, no `ReBaseline` emission, no downstream
announcement; no catalog **source** cell implements `ReBaselineEmitting` (only
the `UnionSetCell` *consumer* reacts to an incoming `ReBaseline`); the
kernel's RESTART re-baseline path is exercised only by a bespoke test cell
(`RestartReBaselineTest`'s `TaggedProducerCell`), and the driver never calls
`ManagedHost.supervise(ref, SupervisionPolicy.RESTART)`; `21-propagation.md`
records the decided design (fresh per-epoch `sourceId`, `ReBaseline` notice,
catch-up reconciliation) as **unimplemented**; and "the landed RESTART
behaviour is the bare local rollback the decision forbids (conflict C-12,
recorded at 30/31 and 20/22)".

**Side 2 — the kernel test says the decided mechanism exists and C-12 is
fixed.**
`kernel/src/test/kotlin/civictech/cell/host/RestartReBaselineTest.kt:24-31`
claims: *"W2.1 (G-42 + G-43, fixes C-12): a producer's outlet mints a fresh
emission epoch on every RESTART … and announces the supersession via a
`ReBaseline` over the ordinary catch-up path (93 I-22 R2/R4) — never the
landed silent same-`sourceId` rollback (C-12)."* Its single test (`:120-159`)
asserts fresh post-restart `sourceId` (`:139-140`), downstream retraction of
un-reasserted pre-crash tags (`:144`), fresh-epoch tag minting without
aliasing (`:149-151`), and dead-lane fencing of a late straggler (`:155-158`)
— against a bespoke `TaggedProducerCell` (`:45-83`), not any catalog cell.

**Side 3 — the concordance says the requirement is uncovered.**
`doc/spec/CONCORDANCE.md:74`: `| 21-REBASE-01 | — | gap |` (and `:168`:
"Coverage gap: requirement '21-REBASE-01' … has no covering scenario").

The spec prose sides with Side 1, in four places, all recording C-12 as an
open code-diverges conflict:

- `doc/spec/20-dataflow-semantics/21-propagation.md:144-145` ("decided in 93
  I-22, **unimplemented**") and `:163-167` ("The landed RESTART (30/31 rule 5,
  M3.5) is exactly the bare local rollback the decision forbids — spawn-time
  checkpoint, same `sourceId` with a rolled-back counter (tag/wave aliasing
  possible), no downstream reconciliation (conflict C-12, recorded at 30/31
  and 20/22)").
- `doc/spec/20-dataflow-semantics/22-consistency.md:108-111` (⚠ CONFLICT
  C-12 block).
- `doc/spec/30-execution-model/31-hosts.md:169-187` (the I-22 redefinition
  note — "the restore-the-spawn-time-checkpoint text above stays
  as-implemented but is no longer endorsed" — followed by the ⚠ CONFLICT
  C-12 block at `:184-187`).
- `doc/spec/20-dataflow-semantics/24-data-cells.md:482-485` (`[24-TAG-02]`'s
  closing sentence: landed RESTART "is exactly the bare rollback this rule
  forbids (⚠ CONFLICT C-12, recorded in 30/31 and 22)").

And one spec voice already doubts Side 1:
`doc/spec/20-dataflow-semantics/24-data-cells.md:436-443` carries an
⚠ EARS-GAP note — *"this 'unimplemented' claim appears stale — the kernel
already contains `ReBaselineEmitting`, `TagState`'s use of it, and
`RestartReBaselineTest` … a spec editor with fuller context should confirm or

These cannot all be true. Either the kernel mechanism is real (then the
dispute's "bare local rollback" sentence and the four spec conflict blocks are
stale, and what is genuinely missing is the *conformance surface* — catalog
cell, driver verb, scenario), or the kernel mechanism is not real (then the
test's "fixes C-12" KDoc overstates and the honest record must say exactly
what landed versus what was decided). The repo must stop carrying both
stories.
