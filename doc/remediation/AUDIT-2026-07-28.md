# Architecture audit 2026-07-28 — report and implementation plan

Incremental audit of the delta `742f7ca..dcfbb33` (168 commits), dominated by
the new inspector subsystem (`:inspect` + `inspect/ui`) built by the
97-inspector-plan run, plus the T01–T12 remediation tail. Method: six parallel
principle auditors (boundary containment, observation purity, spec-led
integrity, parallel models, cohesion, verification architecture) →
dedupe/severity normalization → independent adversarial refutation of every
Critical/High. The finding ledger, declined list, and guardrail record live in
`doc/architecture-decisions.md`; this file carries the design rationale and
the ordered implementation plan.

Prior-audit deferred (⏸) and excluded (✖) rows in `COVERAGE.md` were honored
and are not re-reported.

## Headline

The kernel survived the inspector well: `ManagedHost` did not regrow,
`SingleWriterReplication` converged toward `Replication`, the new
tap/cold/flow seams are cohesive, `:inspect`'s backend tests are the delta's
strongest verification work, and descriptor discipline in the inspector is
exemplary. The debt the delta actually created is **institutional, not
structural**: the subsystem shipped outside every gate the repo owns — CI
(which has never successfully gated anything), the surface ratchets, the
orientation docs, the spec/concord denominator — and the inspector's two hub
files are accreting the way `ManagedHost` once did.

One pre-existing Critical surfaced on the way: **the repo's CI has executed
exactly once, on the delta's final commit, and failed.** Every claim the docs
make about ratchets "gating the build" is currently true only of local
`./gradlew test` runs.

## The coherent move

One theme unifies nearly everything accepted: **make the gates real, then put
the new subsystem inside them.** Concretely, five work packages (W2 is already
done as part of this audit):

### W1 — Revive CI (kills A1; unblocks B5, B13) — first, highest leverage

The two failures are the two-JVM `ExchangeScaffoldTest` cases (pass locally in
under 2 s; blow a 45 s await on the 2-core runner, plausibly compounded by
`org.gradle.parallel=true` landing in this delta).

1. Reproduce on constrained cores (e.g. `--max-workers=1` + cpu-limited
   container) before changing anything.
2. Tag multi-process tests (`@Tag("multi-jvm")` on the `JvmPeer`-based suites).
3. Split CI: a fast lane (everything minus the tag, parallel) and a serial
   multi-JVM lane (`--max-workers=1`, generous awaits). Keep `concord-full` as
   is (it passed).
4. Confirm the `Fail on unexpected untracked files` step actually executes on
   a green build (it has never run).
5. Add the README status badge and turn on required checks for `main`.

**Abandon/replan trigger:** if the failures reproduce locally under
constrained cores *without* contention from sibling Gradle tasks — i.e. they
are a real kernel/wire race, not runner starvation — stop; that is correctness
work under AGENTS.md's failing-seed rule, not CI plumbing. Do not buy green by
raising timeouts until the cause is classified.

### W5 — Kernel seams for observers (kills B2, B9, B10, B11)

Small, independent kernel changes; each wants its own focused test:

1. `LocationRegistry.onPublish`/`onUnpublish` return `AutoCloseable` like
   their four siblings (additive; retires the `attached`-flag workaround and
   the listener leak).
2. `remoteRefs()` beside `localRefs()`, and fire the existing hooks from
   `unpublishRemotes`/`mirrorLink`/`mirrorUnlink`. This retires the
   inspector's 1 Hz shadow sweep (`reconcilePeers`/`discoverRemotes`, ~85
   lines) — the biggest single simplification available in `InspectorModel` —
   and gives the *next* registry consumer a real seam. Own ticket + wire
   tests: it is a registry-semantics change.
3. Payload-agnostic observe attachment on `FanOutlet` (e.g.
   `observe(ref, onEmit): LinkResult` on the existing `putTap` path), so
   out-of-graph observers stop synthesizing dynamic proxies; `Flow.kt`'s
   proxy dance (with its primitive-unboxing hazard) retires. Then shrink
   `.proxy` out of G1's `:inspect` set — the ratchet documents the end state.
4. `snapshotOf`: honor cancellation (check `isCancelled` before running) and
   fail fast (or document + refuse) on schedulers that declare themselves
   single-threaded — `SimulationController.submit` is a bare `PriorityQueue`
   and the first deterministic inspector test would corrupt it silently (B10).
5. `FanOutlet`: iterate `tapOrder`/`consumerOrder` (COW) directly, dropping
   the redundant `.toList()` per message (B11).

`LocationRegistry.Remote.sink`'s `.proxy` type leak stays batched with the
already-deferred `InstanceIndex`/`DeliveryHold` extraction (COVERAGE.md ⏸) so
distribution call sites churn once.

Free riders while in these files: host-label expression deduplication
(`InspectorModel.defaultHostName` called from the server constructor), the
`net` stale comment.

## Ordering and leverage

**W1 → W3 → W4 → W5 → W6.** W1 first because every other verification
investment (including this audit's three new guardrails) only gates reality
once CI runs; it is also the only Critical. W3 is pure prose + one lint and
can proceed in parallel with W1. W4 banks the contract-drift class that
already fired five times. W5 is small kernel seams that delete inspector
complexity (W5.2 alone removes ~85 lines of sweep) — do it before W6 so the
extraction work shrinks. W6 is contained hygiene; its security line-item
(W6.1) can be pulled forward any time.

**Standing constraints for executors:** kernel changes in W5 are additive
public API — each needs the same accessor-style sign-off discipline the
inspector plan used (progress-log rationale, kernel tests). No `concord/`
edits outside W3.5's DISPUTES entry and the W3.4 lint. Respect
`AGENTS.md`'s failing-seed rule in W1. Do not weaken G1–G3 to make anything
pass — amendment policy is in each test header.
