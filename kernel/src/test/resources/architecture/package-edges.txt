# (post-T03 dead-import sweep). One 'from -> to' per line, sorted.

# A new edge here means a new cross-package dependency was introduced --
# either revert it, or add the line here in the same PR, citing why.
# A baseline edge no longer present in code is a warn-only stale line;
# delete it by hand once ArchitectureRatchetTest reports it (the ratchet
# only ever tightens).

# T11-A: link -> control ADDED — hasDampingWitness moved from ManagedHost
# into link/Handshake.kt, next to reconcileNatures (the nature-reconciliation
# code it belongs with); the predicate's Magnitude::class check needs
# civictech.cell.control.Magnitude. The dependency on control is inherited
# from the pre-move code (host -> control already existed), but the EDGE is
# genuinely new: nothing under civictech.cell.link imported .control before.
# Because control -> link already exists, the addition closes a new
# control <-> link 2-cycle, exactly replacing the control <-> host one T11-C
# removes below — 9 direct 2-cycles before T11, 9 after, so T11 does not net
# reduce the entanglement G-63 records (all 20 non-leaf packages remain one
# SCC either way). The zero-edge alternative, if this ever needs revisiting,
# is civictech.cell.port (next to FeedbackInlet/natures, whose port -> control
# edge already exists); link/ was chosen for the reconcileNatures adjacency
# the T11 ticket named.
#
# T11-C: control -> host REMOVED — AttentionPolicy moved host -> control;
# AttentionScheduler.kt's `import civictech.cell.host.AttentionPolicy` was
# the only thing forcing this edge (the control <-> host package cycle
# doc/ARCHITECTURE.md:107/116 flagged as anomalous). No other file under
# civictech.cell.control imports civictech.cell.host.* (verified by grep),
# so the edge is genuinely gone, not just relocated.
#
# T11-D: consistency -> data ADDED — Replication.replicaFrontier moved into
# consistency/ReplicaQuorum.kt (the settlement predicate belongs with
# ReplicaFrontier/WaveFrontier, its interface and consumer, both already in
# .consistency); the predicate reads WatermarkCell.rows/closed/suspended/
# members/slotId, so the file needs civictech.cell.data.WatermarkCell. No
# file under civictech.cell.data imports civictech.cell.consistency.* (also
# verified by grep), so this is a new one-way edge and no new 2-cycle. (It is
# not cycle-free in the transitive sense — data -> link -> nature ->
# consistency already closed a loop back — but per G-63 every non-leaf package
# is in one SCC regardless, so no reachability changes here.)
#
# V1C-KERNEL: cell -> link ADDED -- BoundedRead.kt (the bounded state read's
# types) lives at civictech.cell, beside Stateful.kt, because it is a *cell
# capability* rather than an app-facing view, and StateRead reuses
# civictech.cell.link.Interest verbatim as its `scope` bound. Reuse is the
# decided design (98-inspector-v4-plan/20-wave-neutral-read-design.md 3.5:
# `since` and `scope` "stay exactly where they are ... and are reused verbatim
# in StateRead"); forking a second interest algebra for reads would be a far
# larger change than the edge. No cycle appears that is not already there:
# link -> cell already exists, so cell <-> link closes a 2-cycle exactly the
# way cell <-> port already does, and G-63's single SCC is unchanged. The
# zero-edge alternative, if this ever needs revisiting, is moving Interest
# itself down to civictech.cell -- it imports nothing but java.io.Serializable
# -- which is a deliberate relocation for a ticket that owns link/, not this one.
#
# E2-ALIGN: observe -> control and observe -> protocol ADDED --
# observe/AlignedObserve.kt (the wave-aligned multi-view sink, spec 20/22
# [22-OBS-02]) folds the wave-completeness condition at cell scope, which is
# exactly the frontier machinery those two packages own: it registers a
# Protocols.Progress handler and reads civictech.cell.control.Progress
# (the CP-A3 absorb-ack that retires an absorbing arm), and it tracks
# EdgeOpen/EdgeClose through civictech.cell.protocol's ProtocolSupport /
# Protocols. Both edges are unavoidable for ANY cell that computes
# completeness -- consistency/WaveFrontier.kt and data/op/CoalescingCombineCell.kt
# carry the identical pair (consistency -> control, consistency -> protocol;
# data -> control, data -> protocol are all already baselined) -- and the
# ticket forbids modifying cell.consistency, so mirroring the fold in observe/
# is the decided route (D-COMBINE precedent). No new cycle: nothing under
# civictech.cell.control or .protocol imports civictech.cell.observe (verified
# by grep, and observe has no inbound baseline edge at all), so observe stays a
# sink package and both additions are one-way. The zero-edge alternative would
# be composing an installed WaveFrontier per inlet, which cannot express one
# frontier spanning several inlets -- the structural reason CoalescingCombineCell
# records in its own KDoc.
#
# SEC1-10: evolve -> link ADDED -- Promotion.promote re-authorizes each
# downstream rebind at PRECHECK ("promotion IS a rebind and MUST re-authorize",
# spec 40-distribution/43-security.md §The three seams item 2; 93 I-28 §4.3
# seam 2). Re-authorization is by construction the question link/ owns: the
# check builds a civictech.cell.link.LinkRequest and asks the two endpoints'
# LinkSupport.reauthorize, so a rebind is admitted on exactly the terms a fresh
# handshake would apply. There is no zero-edge form: any expression of the
# check inside evolve/ names LinkRequest/LinkSupport/Linked, and hiding the
# call behind a port/ or membrane/ helper would only relocate the same question
# away from the phase that must ask it -- PRECHECK, since the COMMIT relink
# that follows is documented non-vetoing. No new DIRECT 2-cycle: nothing under
# civictech.cell.link imports civictech.cell.evolve (verified by grep -- the
# two occurrences there are KDoc [] references, which the scanner does not
# count). And no new cycle at all: evolve's one inbound baseline edge is
# `host -> evolve`, and the two packages were already mutually reachable
# before this line existed (evolve -> host -> link one way, link -> nature ->
# consistency -> host -> evolve the other), so evolve and link were already
# inside the single non-leaf SCC G-63 records. This addition changes the
# reachability graph not at all; it makes one existing path direct.
#
# SEC1-23: cell -> proxy ADDED -- BoundaryDenials.kt's dischargeRefusedArgs
# (computenet-usd.2.1, BS-5) discharges the exclusives of a refusal that no
# reporter will sanitize, and the item's acceptance criterion names the
# primitive it must use: `Proxy.discharge` (consume/release only, the
# ManagedHost refusal precedent 02ac610). The zero-edge alternative is a
# six-line reimplementation of that walk beside Owned/Leased in Ownership.kt,
# which is exactly the duplicated discharge logic the criterion forbids -- the
# same "exactly one implementation" rule that keeps the spec-23-R8 sanitizer
# single. Accounting lives at the civictech.cell root by deliberate design (see
# BoundaryDenials.kt's "Where this file lives, and why"), so the seam cannot be
# moved down into a package that already has the edge without giving up the
# reason it is there. The one alternative that IS genuinely zero-edge, if this
# ever needs revisiting: relocate `Proxy.discharge` itself down to
# civictech.cell beside the Owned/Leased it switches on, and let
# civictech.cell.proxy delegate -- proxy -> cell and port -> cell, the edges of
# its two callers (Proxy.discharging, port/Admit), both already exist. That is
# a deliberate relocation of a landed primitive, belonging to a ticket that
# owns proxy/, exactly as V1C-KERNEL above says of Interest -- not this one,
# whose file claim covers neither Proxy.kt nor port/.
# No new cycle: proxy -> cell already exists (Proxy.kt
# imports civictech.cell.Owned/Leased), so this closes a cell <-> proxy 2-cycle
# exactly as cell <-> link and cell <-> port already do, and G-63's single
# non-leaf SCC is unchanged.
