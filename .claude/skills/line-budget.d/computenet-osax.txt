# computenet-osax: metadata.base_branch is a TIMESTAMPED SNAPSHOT that reads as
# standing metadata, and it goes stale within minutes. A review-filed residual
# names the branch under review, and that branch is normally about to merge —
# that is what the review was for. Five instances: computenet-4jpd and
# computenet-dmkp (2026-08-25, the second stale ~15 minutes after it was
# written), computenet-5yavt (PR #870 merged ~2 minutes later), computenet-tlb83
# (merged within the same orchestrator turn), and a FEATURE carrying another
# feature's branch, which would have re-landed a whole other feature's unsquashed
# commits as conflicts.
#
# The failure is silent, not loud: a merged branch's ref still exists on origin,
# so a session that trusts the field gets a plausible worktree cut from spent
# code and re-derives what main already has.
#
# THE FIX IS MECHANICAL and costs no budget: verify-ready.sh, which already runs
# per id at selection — exactly when the check has to happen — now prints
# STALE-BASE / LIVE-BASE / UNCHECKED-BASE beside its verdict, from the branch's
# PR STATE (`gh pr list --head <base> --state all --json state`). Advisory, so
# the READY/BLOCKED contract and the exit codes are untouched. Seven new tests;
# the discrimination was proved by mutation (flipping the STALE label reddens
# exactly one).
#
# NOT from git ancestry. The first draft used
# `git merge-base --is-ancestor origin/<base> origin/main`, which is FALSE for
# every branch this repo has ever landed: merges are squashes, so the squash
# commit is not a descendant of the branch tip. Measured on three merged
# branches; and on a real bead, computenet-utib7 (base_branch=feature/
# computenet-fpml.5, PR #917 merged), the ancestry draft printed LIVE-BASE —
# "cut from it and target the PR at it" — where the PR-state version prints
# STALE-BASE. Its stubbed tests passed throughout, because the stub encoded the
# same misunderstanding as the code.
#
# The +6 is the prose that mechanism cannot carry: 5a saying the field is a
# snapshot to validate rather than metadata to obey, and review.md telling the
# FILER not to set it when the subject will reach main soon — when its PR is
# ready and green, leave the field unset and let the residual be cut from main
# after the merge, which is the normal path anyway. That second half is what
# stops the field being written stale in the first place, and no script can
# decide it.
