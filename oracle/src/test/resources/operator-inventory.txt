# civictech.cell.data.op operator inventory (computenet-4ru.3.2, epic computenet-4ru §9 risk 2;
# facade-filtering rule added by computenet-4ru.15).
#
# Sorted, one name per line: every top-level (non-nested — no '$' in the class file name) class
# civictech.cell.data.op puts on :oracle's test classpath, MINUS Kotlin compiler-generated
# file-facade classes. A `*Kt` classpath name is treated as a file facade when its bare name (the
# name with the trailing "Kt" stripped) matches an existing `<bare>.kt` source file in the
# package — see civictech.oracle.bind.OperatorInventoryTest.isKotlinFileFacade's KDoc for why that
# test is sound rather than merely quieter, and "WHAT THE FILTER DOES NOT COVER" below for the two
# measured edges where it is not exact. What remains below is hand-written
# operator cells, their *Api companion interfaces, and KSP-generated *Base/*Ports classes — all
# real classpath surface this gate protects. civictech.oracle.bind.OperatorInventoryTest (oracle/
# src/test/kotlin/civictech/oracle/bind/OperatorInventoryTest.kt) diffs the package's ACTUAL,
# facade-filtered classes against this list on every :oracle:test run and fails naming what was
# added and what was removed.
#
# WHY THE FILTER IS SOUND (computenet-4ru.15): Kotlin derives a file facade's JVM name directly
# from its own file's base name (`<Bare>.kt` -> `<Bare>Kt`), and the compiler rejects two
# top-level declarations sharing one qualified name in a package — so a hand-written class
# literally named `<Bare>Kt` can never coexist with a `<Bare>.kt` file that itself carries
# top-level declarations. Finding a `<Bare>.kt` file that carries at least one top-level
# declaration therefore proves the matching `<Bare>Kt` classpath entry is the compiler's facade,
# never a hand-written class. Keying off the file's EXISTENCE rather than its declaration count
# is what fixes the false positive this file used to warn about below: adding or removing a file's ONLY
# top-level declaration no longer changes this inventory at all, because the filter keys off the
# file's EXISTENCE, not its declaration count. A genuinely new operator lives in a file that did
# not previously exist, so it is never named `<PreexistingFile>Kt` and is unaffected by this
# filter; a rename of a hand-written class drags its generated `*Base`/`*Ports`/`*Api` names
# (which never end in `Kt`) along with it, so renames are equally unaffected and still redden
# the gate, as they must.
#
# WHAT THE FILTER DOES NOT COVER — two edges measured by the computenet-4ru.15 feature review
# (2026-08-20) and accepted, neither of which occurs in this package today. Both need a name
# ending in `Kt`, which no operator here is named:
#   1. A `<Bare>.kt` with NO top-level declaration emits no facade at all, so a hand-written
#      class literally named `<Bare>Kt` is legal beside it and is silently dropped from the
#      diffed set (measured: a probe file ReviewProbeFacade4ru15.kt declaring only
#      `class ReviewProbeFacade4ru15Kt` reached the classpath and the gate stayed GREEN). A new
#      operator named `<Bare>Kt` next to a declaration-free `<Bare>.kt` is therefore invisible.
#   2. `@file:JvmName("...")` renames a facade away from its file's base name, so that facade is
#      NOT filtered and its churn still reddens the gate — a residual false positive of the old
#      kind, not a false negative (measured: `Added: [ReviewProbeUnrelated4ru15Kt]`).
#
# 75 lines below (was 80 before this filter dropped 5 pre-existing `*Kt` facade lines — EmitKt,
# FlatMapSetCellKt, JoinSetCellKt, OperatorPagingKt, SemiJoinCellKt — each confirmed to match a
# same-named kernel source file: kernel/src/main/kotlin/civictech/cell/data/op/{Emit,
# FlatMapSetCell,JoinSetCell,OperatorPaging,SemiJoinCell}.kt).
#
# UPDATING THIS FILE IS THE MOMENT to also update civictech.oracle.bind.OperatorCatalog's
# registration and the reference model for the changed operator, IN THE SAME CHANGE — that
# pairing is the whole point of this gate (epic computenet-4ru §9 risk 2, decided at breakdown
# on computenet-4ru.3): otherwise a kernel operator can drift out of sync with the oracle's
# registry/reference model with nothing failing to say so. Because the facade filter above
# already removes the false-positive case that used to train readers to bump this file
# reflexively, treat every "Added"/"Removed" entry as real operator-vocabulary churn requiring
# that follow-through — the one exception being edge 2 above (a facade renamed by
# `@file:JvmName`), which no file in this package currently uses.
#
