#
# WHY THE FILTER IS EXACT (computenet-4ru.19, replacing computenet-4ru.15's source-existence
# heuristic): every class the Kotlin compiler emits carries a `kotlin.Metadata` annotation
# distinguishing `FILE_FACADE_KIND` (a file's top-level declarations) from `CLASS_KIND` (an
# ordinary class) unconditionally — this does not depend on the class's name matching any source
# file, so it does not share either edge the old source-existence heuristic had: a hand-written
# class named `<Bare>Kt` beside a declaration-free `<Bare>.kt` now correctly reddens the gate (it
# has `CLASS_KIND`, not `FILE_FACADE_KIND`); a facade renamed by `@file:JvmName(...)` now correctly
# stays filtered regardless of its name (it still carries `FILE_FACADE_KIND`). A genuinely new
# operator's own class always has `CLASS_KIND` and is unaffected by this filter; a rename of a
# hand-written class drags its generated `*Base`/`*Ports`/`*Api` names along with it, and those
# also carry `CLASS_KIND`, so renames are equally unaffected and still redden the gate, as they
# must. Both edges computenet-4ru.15 left open are closed by this rule change — mutation-proven on
# computenet-4ru.19 — and the checked-in list below is unchanged by the switch: the same 5 file
# facades (EmitKt, FlatMapSetCellKt, JoinSetCellKt, OperatorPagingKt, SemiJoinCellKt) are identified
# either way in this package today.
#
